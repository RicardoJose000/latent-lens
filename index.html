The problem

Your model sounds confident. That is the problem. A chatbot is built to produce answers. An evaluation platform is built to judge them, with fixed rubrics, separated judges and scores you can reproduce next week.

Not a chatbot wrapper.
An instrument.

The core architectural difference: a chatbot optimises the next reply. Latent Lens treats every response as evidence and runs it through a deterministic, versioned evaluation pipeline.

Chatbot

Generates

  • One model writes and grades its own output
  • Stateful conversation, temperature > 0
  • Free-text answers, nothing to compare
  • Success = the user stopped asking
Latent Lens

Measures

  • Judge is isolated from the generator
  • Pinned rubric + model version, temperature 0
  • Schema-validated JSON per claim and per instruction
  • Every run stored, diffable and re-runnable
Platform

Six lenses on
every response.

01 / FAITHFULNESS

Claim-level grounding

Responses are split into atomic claims. Each one is checked against your ground truth and labeled supported, partial, contradicted or unsupported, with the exact evidence quoted.

02 / HALLUCINATIONS

Drift & fabrication

Numeric drift, invented entities and flipped polarity are caught and classified, not just flagged.

03 / INSTRUCTIONS

Instruction adherence

Length, format, language, exclusions and required items are extracted from the prompt and verified one by one.

04 / LLM-AS-A-JUDGE

Structured judges, calibrated scores

The judge model only labels items through a strict JSON schema. Scores are computed in code from those labels, so a run is reproducible and the rubric can be audited against human labels.

05 / TAXONOMY

Failure taxonomy

Every defect is mapped to a type and a severity, so you can see which kinds of failure are growing across releases.

06 / REMEDIATION

Actionable fixes

Each failure type comes with a concrete remediation step your engineers can ship: a prompt change, a retrieval fix or a post-generation guard.

How it works

Five frames.
One verdict.

Each evaluation is an async job: queued, processed by workers, persisted in Postgres and streamed back to the dashboard.

01INGEST

Prompt, response, ground truth.

Submitted from the UI or API. Validated, hashed and queued as an evaluation job.

POST /v1/evaluations { prompt, response, context? } -> 202 { id, status: "queued" }
02DECOMPOSE

Claims and constraints.

The response is split into atomic claims. Explicit instructions are extracted from the prompt.

claims: 5 constraints: 2 "refund within 60 days" "avoid: store credit"
03JUDGE

Heuristics + LLM judge.

Deterministic checks run first. An isolated judge labels the rest through a strict JSON schema.

label: "contradicted" evidence: "...within 30 days..." failure: "Numeric drift"
04CALIBRATE

Scores computed in code.

Before each rubric release, weights are checked against a hand-labeled set. When the judge disagrees with humans, we fix the rubric, not the score.

faithfulness = (sup + .5*partial) / n rubric: ll-rubric-0.4 temp: 0
05REPORT

Verdict, taxonomy, fixes.

Stored per user, comparable across runs and exportable as JSON for CI regression gates.

overall: 51 verdict: "High risk" failures: 4 remediation: 4

FAQ
Straight
answers.

    
Written to be quoted. Every answer here is also published as structured data for search engines and AI assistants.

  

  

    
What is the difference between an AI chatbot and an AI evaluation platform?
A chatbot generates answers. An evaluation platform judges answers produced by another system, using an isolated judge, pinned rubric and model versions, schema-validated outputs and stored runs that can be reproduced and compared.

    
How does Latent Lens detect hallucinations?
The response is split into atomic claims and each claim is checked against the supplied ground truth. Claims are labeled supported, partial, contradicted or unsupported, and failures such as numeric drift, fabricated entities and contradictions are classified with a remediation step.

    
Do I need an OpenAI API key?
No. The deterministic evaluation engine runs without any key. An LLM judge can be added later through a provider-agnostic interface.

    
How are evaluation scores calibrated?
Judges only assign labels through a strict JSON schema at temperature 0. Scores are computed in code from those labels and the rubric is tuned against a hand-labeled set until it agrees with human reviewers.
